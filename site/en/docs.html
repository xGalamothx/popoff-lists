PROJECT GUIDE

PopOff documentation

An accessible overview of the problem it aims to solve, how it is organized, and what we have learned along the way.

V24 · Active development

What is PopOff?

PopOff is an experimental extension for Chromium-based browsers, especially Brave, created to reduce pop-ups, unexpected tabs, and unwanted redirects. It is built with Manifest V3 and is still evolving.

It does not promise to block every ad or replace the browser's built-in protections. Its behavior depends on its configuration, available lists, and the techniques used by individual websites.

Main components

Settings interface

Lets users enable protection, manage personal lists, and review operational information.

Service worker

Coordinates settings, network rules, list updates, and navigation events.

Content scripts

Observe selected page behaviors and apply protections permitted by the browser.

Network rules

Uses Declarative Net Request to apply some blocks without processing every request in JavaScript.

Design principles

  • Local privacy: settings and logs are stored in the browser's local storage.
  • Least privilege: optional permissions are requested only when a feature needs them.
  • Layered defense: different protections cover different scenarios; none is considered infallible.
  • Recovery: imports should be validated and users should be able to return to their previous configuration.
  • Compatibility: avoid interfering with media players, legitimate links, or normal browsing.

Development status

The 1.1.10 development build includes basic and advanced settings, an initial diagnostics panel, improved settings backup and recovery, and the new Graphite visual identity. Both DEV and USER packages pass automated tests and packaging checks. Manual validation in Brave is still pending.

Important: automated tests do not replace manual testing in Brave. The project still needs real-world validation across different websites and scenarios.

Why isn't all the code public?

The documentation is shared so others can learn from the process. The protection core and some operational details remain private while their security implications are reviewed. Transparency matters, but so does avoiding the release of information that could make it easier to evade defenses or target users.
